## Problem Statement

자격증 시험 준비생이 기출문제를 편하게 풀어볼 수 있는 도구가 필요하다. 기존 CBT 서비스(comcbt.com 등)는 스토어 설치형 앱이라, 같은 자격증을 준비하는 지인 그룹에게 가볍게 공유하기엔 마찰이 있다.

## What Makes This Cool

실전 시험장의 긴장감(타이머, OMR 느낌)을 웹으로 재현하면서도, 설치 없이 링크 하나로 지인 그룹과 바로 공유해서 같이 풀 수 있다는 점. "혼자 푸는 CBT 앱"이 아니라 "같이 푸는 것"에 방점.

## 데이터 소싱 현황

- 이미 확보됨: `data/exam-questions/{자격증명}/{YYYY-MM-DD}/` 구조로 유기농업기능사 22회차, 종자기능사 30회차, 총 52회차 (source.pdf + raw.md, pymupdf 자동 추출).
- 원본은 comcbt.com(전자문제집 CBT)이 배포한 "교사용" PDF — 문항 내 굵은 원문자(❶❷❸❹)로 정답 표시, 해설은 없음.
- 저작권: `data/exam-questions/README.md`에 이미 명시 — 출제기관/comcbt.com 저작물일 수 있어 로컬 개발·AI 참고용으로만 사용, 원문 그대로 대량 배포 시 별도 라이선스 확인 필요. **이 앱을 지인 그룹 밖으로 공개 배포할 경우 반드시 재검토.**
- 아직 구조화 안 됨: `questions.json`(선택형 정답/보기 구조화 데이터)은 미생성. 앱이 실제로 문제를 렌더링하려면 raw.md → 구조화 데이터 파싱이 선행 작업으로 필요 (Next Steps에 반영).

## Constraints

- 콘텐츠(기출문제 자체)는 comcbt.com 등 기존 서비스와 동일한 원본 데이터라 차별화 요소가 아니다.
- "가볍게" 만드는 사이드/학습용 프로젝트 — 스타트업/수익화 목적 아님.
- 타겟은 불특정 다수가 아니라 같은 자격증을 준비하는 지인 그룹 수준의 소규모.
- 지인 그룹은 모바일 브라우저로 접속할 가능성이 높음 — 모바일 반응형 필수 (OMR 그리드처럼 밀도 높은 UI는 특히 모바일 레이아웃 별도 검토 필요).

## Premises

1. 콘텐츠로는 기존 서비스와 차별화할 수 없다 (같은 원본 데이터) — 동의
2. 차별화는 배포 방식(설치 없는 웹링크 공유)과 실전 몰입감(UX)에서 나와야 한다 — 동의
3. 타겟은 "같은 자격증 준비하는 지인 그룹" 수준의 소규모다 — 동의
4. 전체모의고사 모드와 과목별연습 모드 둘 다 MVP부터 필요하다 — office-hours 세션 이전 대화에서 이미 확정. 채점 방식(즉시피드백/일괄채점)도 원래는 "설정으로 자유 전환"이 요구사항이었으나, 이번 리뷰 라운드에서 Approach B로 구체화하며 1차 릴리즈는 모드별 기본값 고정(전체모의고사=일괄채점, 과목별연습=즉시피드백)으로 축소하고 자유 토글은 2차로 이연하기로 결정함 (Approach B 참고, Open Questions에서 재논의 안 함 — 이 문서 안에서 확정).

## Cross-Model Perspective

독립적인 Claude 서브에이전트(코덱스 미설치로 대체 실행)의 콜드 리드:

- **못 고려한 가장 멋진 버전**: 지인 그룹이 같은 모의고사를 동시에/비동기로 풀고, 종료 후 그룹 리더보드 + 문항별 그룹 오답률을 보는 기능. comcbt류 솔로 드릴링 앱이 구조적으로 못 하는 지점이며, "그룹 링크 공유"라는 배포 방식과 정확히 맞아떨어짐.
- **가장 흥분되는 포인트**: "실전 몰입감 (타이머, OMR 느낌, 긴장감)" — 다른 답변은 전부 CBT 표준 기능(콘텐츠, 자동채점)인데 이것만 감각적/감정적 디테일이 담김. 콘텐츠나 로직이 아니라 시험장의 심리적 압박감 재현이 이 프로젝트의 핵심.
- **기존 도구 활용**: "OMR 느낌 타이머 시험 앱"에 딱 맞는 오픈소스는 없음. 일반 퀴즈 앱 템플릿이 라우팅+문항 상태관리 정도(~30%)만 제공. OMR 버블시트 UI, 시험장 긴장감 타이머, 즉시/일괄 채점 토글, 그룹 리더보드는 직접 구현 필요.
- **주말 프로토타입 제안**: Next.js + Tailwind, 인증 없이 링크 접근, 모의고사 모드(OMR 그리드 답안지 + 카운트다운 타이머) + 과목별 연습 모드(필터 리스트 + 즉시피드백 토글). AI 해설 생성, 계정/인증, 오답노트 영속화, 그룹 리더보드는 이번 스코프에서 제외 권장.

교차 검증: 콘텐츠 무차별화·배포방식 차별화 전제는 그대로 지지됨. "그룹 리더보드"는 기존 대화에 없던 새 아이디어로, Creative 대안(Approach C)에 반영. 전제를 뒤집는 의견은 없었음.

## Approaches Considered

### Approach A: Minimal Viable
카드형 문항 + 카운트다운 타이머 + 일괄채점. Next.js+Tailwind, 인증 없음, 링크 공유. 회차/과목별 선택만 있음.
- 예상 작업량: S, 위험도: 낮음
- 주말 1-2개로 완성 가능

### Approach B: Ideal Architecture (채택)
전체모의고사 모드와 과목별연습 모드는 화면 구성이 다르다:

| | 전체모의고사 모드 | 과목별연습 모드 |
|---|---|---|
| 문항 UI | OMR 그리드 스타일 답안지 (번호 그리드에 답 선택) | 필터링된 문항 리스트 |
| 타이머 | 카운트다운 + 긴장감 연출(예: 잔여 10분부터 색 변화). 기본값: 켜짐(끌 수 없음) | 기본값: 꺼짐. 연습 시작 화면에서 사용자가 선택적으로 켤 수 있음 |
| 타이머 만료 시 | 00:00 도달 시 자동 제출 + 일괄채점 자동 실행 (사용자 액션 불필요) | 타이머를 켠 경우: 답안 입력 잠금 + 미응답 문항 오답 처리 + 요약 결과 화면 표시 (일괄채점 로직과 별개). 끈 경우 해당 없음 |
| 채점 | 일괄채점 고정 (모드 진입 시 자동 적용, 사용자 설정 화면 없음) | 즉시피드백 고정 (문항마다 정오 표시, 사용자 설정 화면 없음) |
| 범위 | 회차 전체 문항 (자격증별로 상이 — 예: 유기농업기능사는 60문항) | 선택한 과목만 |
| 응시 중 이탈 복구 | 새로고침/탭 닫힘/뒤로가기 시 선택한 답과 남은 시간을 브라우저 localStorage에 임시 저장, 재접속 시 복원 (1차 스코프 포함 — 실전 몰입감이 핵심 가치인데 이탈로 진행 상황이 날아가면 신뢰도 직접 훼손) | 동일하게 localStorage 임시 저장 |

- 예상 작업량: M, 위험도: 중
- Premise 4(전체/과목별 모드 둘 다 필요)를 반영하되, 채점 방식은 자유 토글이 아니라 모드별 기본값 고정으로 1차 스코프를 좁힘 — "실전 몰입감"(일괄채점=실전)과 "학습 효율"(즉시피드백=연습) 컨셉이 서로 상충하지 않도록 분리.
- **1차 릴리즈 범위**: 위 표 그대로 (모드별 고정값 + 타이머 만료 자동 처리 + localStorage 이탈 복구). 채점 방식을 사용자가 임의로 뒤집는 토글 UI는 2차로 미룸 — "가볍게" 제약과의 충돌을 줄이기 위한 절충.

### Approach C: Creative/Lateral — Group Experience
Approach A 수준의 미니멀 UI에, 그룹 링크로 지인들과 같은 모의고사를 동시에 풀고 결과를 비교하는 그룹 리더보드 중심. "같이 푸는" 경험이 핵심, UI 몰입감은 후순위.
- 예상 작업량: M, 위험도: 중 (실시간 동기화 복잡도)
- Cross-Model Perspective에서 제안된 아이디어

## Recommended Approach

**Approach B (Ideal Architecture)** — 사용자가 채택. Premise 4로 이미 확정된 요구사항(전체/과목별 모드 둘 다 MVP부터 필요)이 있었기 때문에, Approach A로 축소했다가 다시 확장하는 것보다 처음부터 반영하는 편이 낫다. 다만 리뷰 결과, "가볍게" 제약(Constraints)과의 충돌을 줄이기 위해 채점 방식은 사용자가 고르는 토글이 아니라 모드별 고정값으로 1차 스코프를 좁혔다 (Approach B 표 참고).

Approach C(그룹 리더보드)는 매력적이지만 실시간 동기화 복잡도가 있어 이번 스코프에는 포함하지 않음 — Open Questions에 남겨둠.

## Open Questions

- 오답노트 기능 포함 여부
- 이력/답안 저장을 로컬(기기)에만 할지, 서버+로그인을 붙여 기기 간 동기화할지 — **그룹 리더보드(Approach C)를 나중에 추가할 가능성이 있다면, 로컬전용으로 시작 시 이후 서버 구조로 재설계해야 할 수 있음을 감안해서 결정할 것** (최소한의 익명 세션 기반 서버 저장을 처음부터 고려하는 것도 옵션)
- 해설 콘텐츠 보강 여부 (현재 데이터엔 정답만 있고 해설 없음) — AI 자동 생성은 이번 스코프 제외로 잠정 결론 (Cross-Model 제안)
- 오프라인 지원 여부
- 단일 자격증으로 먼저 출시할지, 처음부터 멀티 자격증(유기농업기능사+종자기능사) 노출할지
- 그룹 리더보드(Approach C)를 이후 버전에 추가할지
- 구체적 기술 스택 (Next.js는 Cross-Model 제안일 뿐, 아직 확정 아님 — CLAUDE.md 기술스택 섹션도 플레이스홀더 상태)
- 자격증별 시험 규격(문항 수, 제한시간, 합격 기준)을 데이터 모델에 어떻게 반영할지 — 지금 확보된 데이터는 문항/보기/정답만 있고 제한시간·합격기준은 미포함. 자격증마다 다를 수 있어 별도 메타데이터 스키마 설계 필요

## Success Criteria

지인 3명에게 링크를 보내서, 추가 설명 없이 막힘없이 (1) 전체모의고사 1회 완주, (2) 과목별연습 1회, 두 모드 모두 문제없이 사용할 수 있으면 성공.

## Distribution Plan

웹앱, 설치 없이 링크 공유로 접근. 구체적 배포 파이프라인(호스팅 등)은 아직 미정 — writing-plans 단계에서 기술 스택과 함께 결정.

## What I noticed about how you think

- 원래 "모바일 앱"으로 요청했지만, "지인들이랑 진짜로 쓸 수 있게 만드는 가장 빠른 길"을 물었을 때 스스로 "웹앱 (링크만 공유하면 바로 접근)"이라고 답하며 방향을 수정했다 — 형식(모바일 앱)보다 목적(빠르게 같이 쓰기)을 우선시하는 판단.
- "실전 몰입감 (타이머, OMR 느낌, 긴장감)"이라는 표현에만 감각적 디테일이 담겨 있었다 — 나머지 답변은 기능 나열이었는데, 여기서만 감정이 묻어났다.
- 콘텐츠 차별화가 불가능하다는 전제를 곧바로 받아들였다 — 방어적으로 반박하지 않고, 이미 알고 있었던 것처럼 동의했다.
